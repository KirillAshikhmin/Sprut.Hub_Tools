## Что должно заработать

Каждое из восьми правил §12 закрыто утверждением, и отдельно — что при нуле механизм молчит.

## Из брифа, дословно

> «раз в указанное количество времени … вентиляция включается»
> «только если до этого она не включалась по присутствию или вручную»

## Разделы спецификации

`spec.md` §12, §10, и §11 в части переименования `purgeMinutes` → `airingMinutes`.

## Критерии приёмки

- [ ] Переименование отражено везде, где тесты ссылались на `purgeMinutes`
- [ ] Контрактный тест опций знает `airingIntervalHours` с дефолтом `0` и `airingMinutes` с дефолтом `5`
- [ ] `airingIntervalHours` = 0 → вытяжка не включается никогда, сколько бы времени ни прошло
- [ ] Интервал истёк, активности нет → включение, ровно `airingMinutes` работы, выключение; границы точные
- [ ] Активность есть в момент истечения интервала → включения нет
- [ ] Обнуление отсчёта: работа по присутствию, ручная и по влажности — каждая переносит следующую вентиляцию на интервал вперёд
- [ ] Запрет автоматики → периодической вентиляции нет
- [ ] Пауза `cooldownMinutes` соблюдается
- [ ] Влажность вентиляцию не продлевает
- [ ] `preset.json` дополнен `airingIntervalHours`, `purgeMinutes` в нём переименована
- [ ] `.tests/SPEC.md` описывает механизм и обнуление отсчёта
