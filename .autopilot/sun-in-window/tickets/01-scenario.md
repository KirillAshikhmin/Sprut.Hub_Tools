# 01 — Сценарий: расчёт положения Солнца и флаг «солнце в окне»

**Требования:** R01, R02, R03, R04, R04.1, R05, R06, R07, R08, R09i, R10i, R10i.1, R10i.2, R11i, R11i.1, R12i, R13i, G01, A01, A02, A03
**Blocked by:** —

**Волна:** 1
**Status:** ready

## Что должно заработать

Логический сценарий Sprut.Hub, который вешается на виртуальный выключатель и держит его
включённым ровно тогда, когда Солнце светит в указанное окно. В настройках — координаты,
направление окна (румб из восьми или точный азимут) и два порога: минимальная высота
Солнца над горизонтом и максимальное отклонение Солнца от направления окна. Сценарий сам
пересчитывает состояние по таймеру в течение дня, сразу после запуска хаба и после каждого
сохранения сценария, и переживает пересохранение без второго живого таймера.

Плюс два файла, без которых сценарий нельзя запустить на стенде: `.tests/config.json`
и `.tests/preset.json`.

## Из брифа, дословно

> «Есть сценарий DayNight, по аналогии сделай сценарий - свет в окне»
> «указывается направление куда выходят окна (Север, Северо-Запад, Запад и т.д.) или точный угол, координаты и сценарий по формуле считает светит ли сейчас свет в окно»
> «Так же можно указать угол падения, меньше какого  перестает считаться присутствием солнца в окне»
> «Сценарий должен ещё учитывать дату»

## Разделы спецификации

Истории 1–19 целиком. Решения §1–§9. Границы и швы — все пять модулей.

Формула в §3 задана полностью, вместе с опорными значениями для проверки — её надо
реализовать как написано, а не подбирать свою.

## Критерии приёмки

- [ ] `info` содержит все десять опций из §5 с указанными типами, диапазонами и значениями по умолчанию; `onStart: true`; двуязычные `name`/`desc`
- [ ] Расчёт положения Солнца соответствует §3 и проходит четыре опоры из таблицы §3 с допуском 0,5°
- [ ] Одно и то же время суток 21 июня и 21 декабря даёт разный результат для одного окна (G01)
- [ ] Правило §4 с круговой разностью азимутов: окно на 350° и Солнце на 10° — это отклонение 20°
- [ ] Точный азимут `−1` означает «не задан» и отдаёт решение румбу; любое значение 0…360, включая 0, перебивает румб
- [ ] Ночью и при высоте Солнца ниже порога флаг снят; полярный день и полярная ночь отдельной ветки не требуют
- [ ] Неверные координаты: одна строка ошибки в лог, характеристика не записывается, таймер не ставится (§9)
- [ ] Пересчёт по таймеру с интервалом из опции; после пересохранения сценария старое поколение таймера прекращается (`global["SIW_gen_" + uuid]`)
- [ ] Два экземпляра на разных окнах не мешают друг другу
- [ ] Опции `invert`, `allowManualControl`, `changeServiceName` работают как в `DayNight`
- [ ] Одинаковое значение в характеристику повторно не пишется; в лог пишем только смену состояния
- [ ] `jjs -scripting --language=es6 -co` компилирует файл без ошибок
- [ ] `.tests/config.json` и `.tests/preset.json` есть; `bun run cli run SunInWindow --root ..` запускается, `bun run cli serve` показывает сценарий с рабочей ручной проверкой
