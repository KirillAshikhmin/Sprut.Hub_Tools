# Поведенческая спецификация сценария «Кодовый замок» (CodeLock)

Документ описывает наблюдаемое поведение сценария так, чтобы по нему можно было написать тесты, не заглядывая
в исходный код. Всё, что здесь утверждается, — контракт; всё, что явно названо неспецифицированным, тестировать не нужно.

## 1. Что делает сценарий

Логика применяется к целевому устройству и разблокирует его, когда пользователь набрал на выбранных кнопках
верный код. Кнопки задаются опциями, целевое устройство — то, к которому применена логика.

Точка входа — `trigger(source, value, variables, options, context)`. Кроме того, сценарий подписывается на события
кнопок: изменение характеристики `ProgrammableSwitchEvent` любого сервиса `StatelessProgrammableSwitch` или
`Doorbell` вызывает обработку нажатия. `ProgrammableSwitchEvent` — событийная характеристика: запись того же
значения повторно считается новым событием.

Значения события: `0` — одиночное нажатие, `1` — двойное, `2` — долгое.

### 1.1. Куда пишется результат

Характеристика для записи определяется **типом сервиса**, к которому применена логика:

| Тип сервиса | Характеристика | Значение при верном коде |
|---|---|---|
| `LockMechanism` | `LockTargetState` | `0` |
| `SecuritySystem` | `SecuritySystemTargetState` | `3` |
| `Switch`, `Lightbulb`, `Outlet` | `On` | `true` |
| `GarageDoorOpener` | `TargetDoorState` | `0` |

Важно: `trigger` может прийти по любой характеристике из `info.sourceCharacteristics`, в том числе по
`LockTargetState` сервиса `GarageDoorOpener` (у ворот это допустимая необязательная характеристика).
Записывается всё равно характеристика из таблицы, выбранная по типу сервиса.

Если тип сервиса не из таблицы, сценарий пишет ошибку в журнал (`console.error`) и не меняет ничего.

## 2. Опции

| Ключ | Тип | Дефолт | Смысл |
|---|---|---|---|
| `code` | строка, до 128 символов | `""` | код (см. §3) |
| `allowExtraPresses` | булево | `false` | разрешить лишние нажатия до и после кода |
| `button1`…`button9`, `button0` | строка (UUID сервиса `"aid.sid"`) | `""` | кнопки, соответствующие цифрам кода |
| `enterButton` | строка (UUID сервиса) | `""` | необязательная кнопка подтверждения |
| `pressTimeout` | целое 0–300 | `10` | максимальная пауза между нажатиями, секунды; `0` — без ограничения |
| `restoreDelay` | целое 0–3600 | `0` | автовозврат прежнего состояния, секунды; `0` — выключен |
| `debug` | булево | `false` | подробный журнал |

## 3. Формат кода

Код — последовательность шагов «кнопка + тип нажатия». Разбор посимвольный, регистр не важен.

- Цифра `0`–`9` открывает новый шаг на соответствующей кнопке с типом «одиночное».
- Буква `S`/`D`/`L` (и кириллические `С`/`Д`/`Л`) задаёт тип нажатия последнему шагу: одиночное / двойное / долгое.
- Если буква идёт, когда шагов ещё нет, шаг создаётся на **кнопке 1**.
- Если у последнего шага тип уже задан явно, следующая буква открывает **новый** шаг на той же кнопке.
- Символы `пробел`, `таб`, `,` `.` `-` `+` `_` игнорируются.
- Любой другой символ делает код невалидным.

| Код | Разбирается как |
|---|---|
| `12357` | 1 одиночное, 2 одиночное, 3 одиночное, 5 одиночное, 7 одиночное |
| `SSDL` | кнопка 1: одиночное, одиночное, двойное, долгое |
| `1S 2S 1D 2S` | 1 одиночное, 2 одиночное, 1 двойное, 2 одиночное |
| `0D9L` | 0 двойное, 9 долгое |
| `1SS` | 1 одиночное, 1 одиночное |
| `SS1` | 1 одиночное, 1 одиночное, 1 одиночное |
| `1С 2Д` | 1 одиночное, 2 двойное |
| `1X`, `""`, строка только из разделителей | невалидный код |

Максимальная длина кода — 32 шага.

## 4. Режимы проверки

Комбинация «выбрана ли кнопка ввода» × «включены ли произвольные нажатия» даёт четыре режима:

| Кнопка ввода | `allowExtraPresses` | Поведение |
|---|---|---|
| нет | `true` | сравниваются последние N нажатий (N — длина кода); лишние нажатия перед кодом не мешают |
| нет | `false` | нажатия сверяются по позиции с начала кода; первое несовпадение блокирует ввод |
| есть | `true` | по одиночному нажатию кнопки ввода код ищется как непрерывный фрагмент набранного |
| есть | `false` | по одиночному нажатию кнопки ввода набранное должно точно совпасть с кодом |

Дополнительно:

- В строгом режиме без кнопки ввода после ошибки ввод заблокирован: любые нажатия игнорируются, пока между
  нажатиями не пройдёт пауза больше `pressTimeout`. Нажатия, пришедшие во время блокировки, отсчёт паузы
  продлевают — непрерывная серия нажатий блокировку не снимает.
- В режимах с кнопкой ввода блокировки нет: после неудачной попытки следующую можно начинать сразу.
- Успешный ввод очищает набранное. Нажатие кнопки ввода очищает набранное независимо от результата.
- При включённых произвольных нажатиях с кнопкой ввода хранится не более 64 последних нажатий.

## 5. Задержка на ввод

Перед обработкой каждого учтённого нажатия сравнивается пауза с момента предыдущего учтённого нажатия:

- пауза **строго больше** `pressTimeout` секунд — набранное сбрасывается, блокировка снимается;
- пауза ровно в `pressTimeout` — набранное сохраняется;
- `pressTimeout = 0` — сброса по времени нет вообще.

Правило действует во всех режимах, включая нажатие кнопки ввода: если после набора кода выждать паузу больше
`pressTimeout`, подтверждение уже ничего не откроет.

## 6. Какие события учитываются

- События кнопок, выбранных в полях `button1`…`button0`, — учитываются как шаги кода.
- Одиночное нажатие кнопки из `enterButton` — подтверждение ввода.
- Двойное и долгое нажатие кнопки ввода игнорируются полностью: не подтверждают, не попадают в набранное,
  не сбрасывают его и не участвуют в отсчёте пауз.
- События кнопок, не выбранных ни в одном поле, игнорируются полностью: не влияют ни на набранное, ни на
  отсчёт паузы, ни на блокировку. В частности, посторонняя кнопка не может продлить окно ввода или снять блокировку.

## 7. Автовозврат

При верном коде сценарий запоминает состояние целевой характеристики **до** записи и, если `restoreDelay > 0`,
через `restoreDelay` секунд возвращает его.

- Пока автовозврат запланирован, повторный верный код не перезаписывает запомненное состояние — таймер просто
  перезапускается. То есть возвращается состояние, которое было до **первого** из серии вводов.
- После того как автовозврат отработал (или был отменён), следующий верный код запоминает состояние заново.
- Любое изменение целевой характеристики извне (ручное управление, другой сценарий), а также сохранение
  сценария в UI отменяют запланированный автовозврат.
- Собственная запись сценария автовозврат не отменяет.
- `restoreDelay = 0` — автовозврат не планируется.

## 8. Собственные записи (эхо)

Сценарий пишет в ту же характеристику, на которой висит, поэтому получает `trigger` от собственной записи.
Такой вызов игнорируется целиком: не оформляет подписку, не обновляет снимок опций, не отменяет автовозврат.

Контекст, который передаёт хаб, всегда содержит собственный фрейм логики вида `LOGIC[Logic/<i>/<service>/]`,
дальше — цепочка источника (`C[...]`, `HUB[OnStart]`, `WEB[...]`, `CLOUD[...]`, другой `LOGIC[...]`).
Эхом считается цепочка, в которой фрейм этой же логики встречается более одного раза. Обычный вызов с одним
фреймом логики эхом не считается и обрабатывается нормально.

## 9. Реакция на изменение настроек

`trigger` вызывается при старте хаба и при каждом сохранении сценария. На каждом не-эхо вызове сценарий заново
читает опции: смена кода, состава кнопок, режима, задержек применяется **без перезагрузки хаба**.
Подписка на кнопки оформляется один раз и повторными вызовами не дублируется.

## 10. Ошибки конфигурации

При любой из ситуаций ниже сценарий пишет `console.error` и не реагирует на нажатия, пока настройки не исправят
и не сохранят сценарий:

1. Код пуст или содержит недопустимый символ.
2. В коде больше 32 шагов.
3. Код использует цифру, поле кнопки для которой не заполнено.
4. Одна и та же кнопка выбрана более чем в одном поле, включая поле кнопки ввода.
5. Кнопка ввода не выбрана, произвольные нажатия выключены и `pressTimeout = 0` — снять блокировку после ошибки
   было бы нечем.

Подписка на кнопки оформляется даже при невалидной конфигурации, поэтому после исправления настроек сценарий
начинает работать сразу после сохранения.

## 11. Журнал

| Событие | Уровень |
|---|---|
| Верный код, устройство разблокировано | `info` |
| Неверный код по нажатию кнопки ввода при непустом наборе | `info` |
| Нажатие кнопки ввода при пустом наборе | только при `debug: true` |
| Ошибка конфигурации | `error` |
| Разбор нажатий, сброс по паузе, блокировка, планирование и срабатывание автовозврата | только при `debug: true` |

## 12. Неспецифицированные зоны

Тестировать не нужно, поведение намеренно не закреплено:

- порядок и формулировки конкретных текстов в журнале (кроме уровня и факта наличия записи);
- поведение при одновременном приходе двух событий кнопок в один момент виртуального времени;
- содержимое списка кнопок в выпадающих опциях (формируется из состояния хаба на момент загрузки сценария);
- состояние после перезагрузки хаба, кроме того, что набранное теряется, а запланированный автовозврат не восстанавливается.
