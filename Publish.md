# Публикация сценариев — `./publish`

Инструмент готовит сценарий Sprut.Hub к публикации: **генерирует `.json`-экспорт из `source/*.js`**, прогоняет все проверки и (опционально) собирает zip-архив. Источник правды — `source/*.js` (+ манифест `publish.json`), а `.json` генерируются командой.

## Быстрый старт

```bash
# Интерактивно: просто запустите без аргументов — выберете сценарий и параметры в меню
./publish

# Или сразу конкретный сценарий
./publish VirtualThermostat            # полный прогон: проверки → генерация JSON → тесты → архив
./publish VirtualThermostat --check    # только проверки, без записи (посмотреть, что будет)
```

**Требования:** установленный [Bun](https://bun.sh) и один раз `cd ScenarioSimulator && bun install`.

## Интерактивный режим

Запуск `./publish` без имени сценария (в терминале) открывает меню:

1. **Выбор сценария** — нумерованный список всех сценариев с папкой `source/`. Введите номер или часть имени (например `therm` → `VirtualThermostat`). Пустой ввод — выход.
2. **Режим** — `[1]` полный (запись), `[2]` только проверка, `[3]` только создать `publish.json`.
3. **Тесты** — прогонять ли тесты симулятора.
4. **Changelog** — считать отсутствие записи ошибкой или предупреждением.

Результат (ошибки, предупреждения, тесты, что сгенерировано) печатается тут же; затем можно выбрать следующий сценарий.

## Флаги (не-интерактивный режим)

| Флаг | Действие |
|---|---|
| `--check` / `--dry-run` | Только проверки + список изменений, **без записи** на диск |
| `--init` | Создать `publish.json` (если отсутствует) и выйти |
| `--no-tests` | Пропустить прогон тестов сценария |
| `--allow-missing-changelog` | Отсутствие записи в changelog → предупреждение, а не ошибка |
| `-i`, `--interactive` | Принудительно интерактивный режим |
| `--root <dir>` | Корень репозитория (по умолчанию вычисляется автоматически) |

## Модель работы: «сначала все проверки, потом решение»

Команда **не прерывается на первой ошибке**. Сначала выполняются все проверки, результаты собираются:

- **Есть хотя бы одна ошибка** → печатается весь список ошибок и предупреждений, **на диск ничего не пишется**, код возврата ≠ 0.
- **Ошибок нет** → генерируются `.json`, при отсутствии создаётся `publish.json`, собирается архив, код возврата 0.

Предупреждения (⚠️) не блокируют запись.

## Что проверяется

| Проверка | Уровень | Что ловит |
|---|---|---|
| Синтаксис + неподдерживаемые конструкции | ошибка | ParseError и запрещённые в Nashorn узлы (классы, `import/export`, `async/await`, `...spread`, деструктуризация, `?.`) |
| Метаданные `info` | ошибка | у LOGIC есть `name`/`description`/`version`; читаются «по коду» — литералы, `IDENT.ru`, конкатенация строк, константы |
| Changelog | ошибка¹ | в README «История изменений» есть запись под текущую версию |
| Коллизии | ошибка | два исходника пишут в один и тот же JSON |
| Сироты | ⚠️ | JSON в папке, не привязанный к исходнику в манифесте |
| Дрейф версии | ⚠️ | код изменился, а версию не подняли |
| Тесты | ошибка | прогон тестов сценария (эквивалент `sim run`); отключается `--no-tests` |

¹ `--allow-missing-changelog` понижает до предупреждения.

## Манифест `publish.json`

Лежит в корне папки сценария; описывает соответствие `source/*.js` → выходной JSON и метаданные глобальных сценариев (у них нет блока `info`). Если файла нет — **создаётся автоматически** при первом прогоне (проверьте результат; для первого раза удобен `--check`). Полная схема — `ScenarioSimulator/schemas/publish.schema.json`.

```jsonc
{
  "archive": "CircadianLight.zip",          // опц.: имя zip ИЛИ true (=> <Папка>.zip)
  "files": [
    { "source": "source/Логический.js", "primary": true },   // основной LOGIC — его версия идёт в changelog
    { "source": "source/Глобальный.js",
      "json": "Циркадное освещение. Глобальный.json",
      "name": "Циркадное освещение. Глобальный",             // для GLOBAL: имя (у него нет info)
      "archive": true }                                      // включить в zip
  ]
}
```

Поля записи `files[]`: `source` (обяз.), `json` (по умолчанию `<Имя папки>.json`), `type`, `name`, `desc`, `active`, `sync`, `primary`, `archive`.

- **Тип** определяется по содержимому: `info` + `trigger`/`compute` → LOGIC; `update()` без `info` → TEMPLATE; иначе GLOBAL.
- **Версия для changelog** — из `info.version` логического файла; при нескольких логических пометьте основной `"primary": true` (иначе при разных версиях будет ошибка `version-ambiguous`). Для чисто глобальных папок — верхнеуровневое `"version"` в манифесте.
- Для GLOBAL/TEMPLATE `name`/`desc` берутся из манифеста → существующего JSON → имени папки; `onStart` у них не эмитится. Для LOGIC `active`/`sync` при отсутствии в `info` сохраняются из существующего JSON (состояние деплоя).

## Запуск из IntelliJ IDEA / WebStorm

В папке `.run/` лежат готовые конфигурации (появятся в списке Run/Debug):

- **Publish (интерактивно)** — запускает `./publish` в терминале IDE.
- **Simulator: веб-интерфейс** — `./sim serve --port 5173`.
- **Simulator: все тесты** — `./sim run`.

Требуется бандл-плагин **Shell Script** (включён по умолчанию).

## Помощник `./sim`

Запуск любой команды симулятора из корня без `cd`:

```bash
./sim run [Сценарий]        # тесты
./sim serve --port 5173     # веб-интерфейс
./sim list                  # список тестов
./sim validate [Сценарий]   # только AST-проверка ES5+
./sim publish <Сценарий>    # то же, что ./publish
```

## Частые находки и что делать

- **`changelog-missing`** — вы подняли `version`, но в README нет записи под неё. Добавьте раздел в «История изменений».
- **`version-ambiguous`** (многофайловые пакеты) — несколько логических файлов с разными версиями. Пометьте основной `"primary": true` в `publish.json`.
- **`orphan`** (⚠️) — в папке есть `.json`, не привязанный к исходнику. Либо добавьте файл в манифест, либо удалите устаревший JSON.
- **`version-drift`** (⚠️) — код изменился с прошлой генерации, а версия та же. Поднимите версию и допишите changelog.
- **`info-nonliteral`** — `name`/`description`/`version` не удаётся прочитать статически (например, чистый вызов функции без литеральной части). Оставьте хотя бы литеральную часть строки.

## Политика JSON-экспортов

Раньше `.json` сценариев считались экспортами из UI хаба и правились вручную. Теперь **они генерируются из `source/*.js`** этой командой — редактировать их руками не нужно (правки затрутся при следующей генерации). См. также `CLAUDE.md` → «Публикация сценария».
