# ☀️ Солнце в окне
Логический сценарий

> **Держит выключатель включённым ровно тогда, когда Солнце светит в указанное окно**

Логический сценарий для Sprut.Hub, который по координатам дома и направлению окна считает, где сейчас находится Солнце, и поднимает флаг «солнце в окне». Положение Солнца считается на текущие дату и время, поэтому момент «загорелось» сам смещается изо дня в день и от января к июню — настраивать календарь вручную не нужно.

Сценарий даёт только флаг: что с ним делать — решает ваша автоматизация поверх этого выключателя. Границы задачи перечислены в разделе [«Чего сценарий не делает»](#-чего-сценарий-не-делает).

---

## ⚠️ Важные замечания

1. **Румб — это сторона, на которую окно смотрит НАРУЖУ.** Не та, откуда вы смотрите в комнату, а та, куда направлен взгляд из окна. «Запад» значит, что солнце светит в это окно во второй половине дня. Это самое частое место ошибки при настройке.

2. **Координаты нужно ввести заново.** Сценарий не имеет доступа к координатам хаба, даже если они там указаны, — см. [«Широта»](#параметр-широта).

3. **Неверные координаты, направление окна или пороги останавливают сценарий целиком.** Он пишет одну строку в журнал и больше ничего не делает — намеренно, чтобы флаг не врал. Подробности и таблица проверок — в разделе [«Что происходит при неверных настройках»](#что-происходит-при-неверных-настройках).

---

## 💡 Зачем это нужно?

**Проблема:** окна выходят на запад, летом после обеда солнце бьёт прямо в комнату — жарко и на экране блики. Расписание по часам тут работает плохо: момент каждый день разный.

**Решение:** виртуальный выключатель, который включён ровно в это время. Дальше это обычная сущность хаба — по ней закрываются шторы, гаснет подсветка, приходит уведомление.

---

## 📋 Пошаговая инструкция

### Шаг 1: Создание виртуального устройства

Создайте виртуальное устройство типа **«Выключатель»** (Switch) с характеристикой **Включен**. Подойдут также **Розетка** (Outlet) и **Лампочка** (Lightbulb) — у всех трёх есть характеристика `Включен` (`On`), именно её сценарий и пишет.

Назовите устройство по окну, например «Солнце в гостиной» — если окон несколько, устройств тоже будет несколько.

### Шаг 2: Импорт сценария

1. Скачайте файл `SunInWindow.json` из папки сценария
2. Импортируйте сценарий через интерфейс Sprut.Hub:
   - Сценарии → + → Импортировать шаблон → выберите скачанный файл
3. Откройте настройки созданного устройства
4. Перейдите в раздел **«Логика»**
5. Выберите сценарий **«☀️ Солнце в окне»**
6. Настройте параметры сценария (см. ниже)
7. Активируйте сценарий переключателем «Активно»

**ВАЖНО!** При изменении любого параметра после активации сценария перезапустите сценарий переключателем «Активно» сверху. Новые значения опций подхватываются при следующем запуске сценария — проактивного перечитывания настроек нет.

### Шаг 3: Настройка параметров

Обязательный минимум — три значения: **широта**, **долгота** и **направление окна**. Остальные семь параметров можно оставить по умолчанию: со значениями из коробки сценарий даёт «солнце перед окном и выше 5° над горизонтом», чего для первой проверки достаточно.

Сузить срабатывание до «солнце бьёт в стекло» помогут два порога — они разобраны ниже вместе с остальными параметрами.

## ⚙️ Параметры

Порядок в интерфейсе: описание → координаты → направление окна → пороги → поведение.

| Параметр | Ключ | Диапазон | По умолчанию |
|---|---|---|---|
| Широта | `latitude` | −90 … 90 | 55.7558 (Москва) |
| Долгота | `longitude` | −180 … 180 | 37.6173 (Москва) |
| Направление окна | `windowDirection` | список из 8 румбов | Юг (180°) |
| Точный азимут окна | `windowAzimuth` | −1 … 360 | −1 (не задан) |
| Минимальная высота солнца | `minSunAltitude` | 0 … 90° | 5° |
| Максимальное отклонение от направления окна | `maxAzimuthDeviation` | 1 … 90° | 90° |
| Интервал пересчёта (минуты) | `updateInterval` | 1 … 60 | 1 |
| Возможность ручного управления | `allowManualControl` | да / нет | Нет |
| Менять имя сервиса | `changeServiceName` | да / нет | Нет |
| Инвертировать | `invert` | да / нет | Нет |

### Параметр «Широта»

Географическая широта дома в десятичных градусах. Например:
- **55.7558** — Москва (значение по умолчанию)
- **59.9343** — Санкт-Петербург

Диапазон значений: от −90 до 90 градусов.

**Где взять координаты:** их можно посмотреть в настройках хаба в разделе **«Дата и время»**, если вы их там указывали. Сценарий не имеет доступа к этим сведениям, поэтому значения необходимо ввести повторно.

Параметр обязателен: пустое или нечисловое значение останавливает сценарий (см. [«Что происходит при неверных настройках»](#что-происходит-при-неверных-настройках)).

### Параметр «Долгота»

Географическая долгота дома в десятичных градусах, **восточная долгота — положительная**. Например:
- **37.6173** — Москва (значение по умолчанию)
- **30.3351** — Санкт-Петербург

Диапазон значений: от −180 до 180 градусов. Параметр обязателен.

### Параметр «Направление окна»

Сторона света, **на которую окно смотрит наружу** (см. замечание 1 в начале файла).

| Румб | Азимут | Когда солнце светит в такое окно |
|---|---|---|
| Север | 0° | практически никогда (в наших широтах — только летом на рассвете и закате) |
| Северо-Восток | 45° | раннее утро летом |
| Восток | 90° | утро |
| Юго-Восток | 135° | утро и первая половина дня |
| Юг | 180° | середина дня, зимой — почти весь светлый день |
| Юго-Запад | 225° | вторая половина дня |
| Запад | 270° | вторая половина дня и вечер |
| Северо-Запад | 315° | поздний вечер летом |

Значение по умолчанию — **Юг (180°)**. Список закрытый: значение, которого в нём нет, сценарий считает ошибкой и останавливается — молча подставить Юг значило бы отвечать про чужое окно.

### Параметр «Точный азимут окна»

Если окно не смотрит ровно в одну из восьми сторон, впишите его азимут числом: **0 — Север, 90 — Восток, 180 — Юг, 270 — Запад**, отсчёт по часовой стрелке. Дробные значения допустимы: окно можно задать как **300.9**.

**Точный азимут перебивает румб.** Любое значение от 0 до 360 включительно, в том числе **0** (это законный Север, а не «пусто»), отменяет выбор в списке «Направление окна». Значение 360 эквивалентно 0.

**Незаполненное поле означает «беру направление из списка».** Значение по умолчанию — **−1**, именно оно и означает «не задан». Ноль для этого не годится — он занят Севером, поэтому «пусто» пришлось выразить значением вне рабочего диапазона. Пустое поле и поле из одних пробелов тоже считаются «не задан»: сценарий работает по румбу и никаких ошибок не пишет.

Это **единственная необязательная опция сценария**. Ошибкой считается только непустое значение, которое не разбирается в число (например «юг»), либо число вне 0…360 (400, −5).

### Параметр «Минимальная высота солнца»

Высота Солнца над горизонтом в градусах, ниже которой солнце **не считается** светящим в окно, каким бы ни был азимут.

Этот порог решает сразу несколько задач одним числом:
- **отсекает ночь** — ночью высота отрицательна, флаг снят всегда;
- **отсекает сумерки и низкое солнце**, которое всё равно закрыто соседними домами, забором и деревьями;
- **закрывает полярную ночь** без отдельной настройки (см. [«Известные ограничения»](#-известные-ограничения), п. 5).

Диапазон значений: от 0 до 90 градусов. По умолчанию — **5°**.

Как подбирать: 0–3° — «считать любое солнце над горизонтом»; 5–10° — типовой городской двор; 15–20° — если напротив стоит многоэтажка и низкое солнце до вас не доходит.

### Параметр «Максимальное отклонение от направления окна»

Насколько далеко Солнце может уйти в сторону от направления окна и всё ещё считаться светящим в него. Задаёт ширину сектора вокруг направления окна.

- **90°** (по умолчанию) — вся передняя полуплоскость: солнце считается «в окне», пока оно вообще находится перед окном, а не за стеной. Фильтр по азимуту фактически отключён.
- **60°** — умеренное сужение: солнце заметно косит, но всё ещё заглядывает в комнату.
- **45°** — только «в лоб» плюс-минус: узкий сектор, солнце бьёт почти прямо в стекло.
- **1°** — минимально возможное значение, буквально момент точного совпадения.

Диапазон значений: от 1 до 90 градусов.

Отклонение считается **по кругу**: окно на 350° и солнце на 10° — это отклонение 20°, а не 340°.

### Два порога вместе

Пороги **независимы**, и каждый может «завалить» результат в одиночку:

| Высота Солнца | Отклонение от окна | Результат |
|---|---|---|
| ниже порога | любое | флаг снят |
| выше порога | больше порога | флаг снят |
| выше порога | в пределах порога | **флаг поднят** |

Высота отвечает на вопрос «солнце вообще светит?», отклонение — «светит ли оно именно в это окно?».

### Параметр «Интервал пересчёта (минуты)»

Как часто в течение дня пересчитывается положение Солнца. Диапазон: от 1 до 60 минут, по умолчанию — **1**.

Нагрузка на хаб крошечная: расчёт чисто арифметический, а в журнал пишутся только реальные смены состояния. Интервал напрямую задаёт точность срабатывания (см. [«Известные ограничения»](#-известные-ограничения)).

В отличие от остальных числовых параметров, неверный интервал **не останавливает сценарий**, а зажимается в диапазон: 0 станет 1, 999 станет 60. Неверный интервал — не повод перестать отвечать на вопрос «светит ли солнце в окно».

### Параметр «Возможность ручного управления»

- **Нет** (по умолчанию) — сценарий восстанавливает расчётное состояние при любом чужом изменении. Переключить выключатель «назло сценарию» не получится: состояние откатится на ближайшем пересчёте.
- **Да** — сценарий меняет состояние только в момент, когда солнце вошло в окно или вышло из него, а также при запуске хаба и при сохранении сценария. Между этими моментами ваше значение не откатывается.

Ручное удержание не переживает перезапуск хаба и пересохранение сценария — почему так, объяснено в разделе [«Переменные сценария»](#-переменные-сценария).

### Параметр «Менять имя сервиса»

Если включено, имя сервиса автоматически переключается между **«Солнце в окне»** и **«Солнца в окне нет»**.

Имя отражает **реальное положение Солнца**, а не значение характеристики: при включённой инверсии выключатель показывает обратное, а имя всё равно говорит правду о том, что происходит за окном.

### Параметр «Инвертировать»

Меняет записываемое значение на обратное: выключатель **отключён**, пока солнце светит в окно, и **включён** всё остальное время.

Полезно, если автоматизация читает флаг как «можно», а не как «солнце».

## 🧩 Переменные сценария

`variables` — это **внутреннее состояние сценария между вызовами**. Пользователем они не настраиваются, в интерфейсе не показываются и вручную меняться не должны; список приведён для тех, кто читает исходник.

| Переменная | Что хранит |
|---|---|
| `initialState` | признак «первый успешный расчёт в этом запуске уже был» |
| `lastState` | последнее рассчитанное значение флага «солнце в окне» |
| `generation` | поколение таймеров этого экземпляра сценария |
| `generationKey` | ключ поколения, привязанный к UUID сервиса |
| `timerTask` | текущая задача пересчёта |

**Переменные сбрасываются при перезапуске хаба и при каждом сохранении сценария.** Именно отсюда следует поведение ручного управления: удержанное вручную состояние живёт в `variables`, поэтому после перезапуска хаба или пересохранения сценария оно не восстанавливается — первый же расчёт запишет расчётное значение независимо от опции «Возможность ручного управления». Это осознанное поведение по образцу сценария `DayNight`, а не дефект.

## 🔧 Примеры использования

> Во всех примерах сценарий отвечает только за флаг «солнце в окне». Условия «жарко» и «я за компьютером» добавляются в вашу автоматизацию сверху — почему именно так, в разделе [«Чего сценарий не делает»](#-чего-сценарий-не-делает).

### Пример 1: Закрывать шторы, когда солнце греет комнату

Окно на запад, летом после обеда в комнате духота.

- **Широта:** 55.7558
- **Долгота:** 37.6173
- **Направление окна:** Запад (270°)
- **Точный азимут окна:** −1 (не задан)
- **Минимальная высота солнца:** 10 (низкое солнце закрывает дом напротив)
- **Максимальное отклонение от направления окна:** 75
- **Интервал пересчёта:** 5
- **Инвертировать:** Нет

Дальше в блочном сценарии: «если выключатель „Солнце в гостиной“ включён **и** температура в комнате выше 25 °C — закрыть штору».

### Пример 2: Убрать блики на экране

Рабочий стол у юго-западного окна, во второй половине дня солнце светит прямо в монитор.

- **Широта:** 55.7558
- **Долгота:** 37.6173
- **Направление окна:** Юго-Запад (225°)
- **Точный азимут окна:** −1 (не задан)
- **Минимальная высота солнца:** 5
- **Максимальное отклонение от направления окна:** 45 (только когда солнце бьёт почти в лоб)
- **Интервал пересчёта:** 1
- **Менять имя сервиса:** Да
- **Инвертировать:** Нет

Дальше: «если выключатель включён **и** компьютер в сети — опустить рулонную штору на 60 %».

### Пример 3: Окно под нестандартным углом

Дом развёрнут, окно смотрит на 247°.

- **Направление окна:** любое из списка (в расчёте не участвует)
- **Точный азимут окна:** 247
- **Минимальная высота солнца:** 5
- **Максимальное отклонение от направления окна:** 90

Точный азимут перебивает список, поэтому выбранный там румб в расчёте не участвует. Но выбран он всё равно должен быть из списка: проверку румб проходит всегда, даже когда направление берётся из точного азимута.

### Пример 4: Несколько окон в квартире

Сценарий вешается на несколько виртуальных выключателей сразу, у каждого свои настройки: «Солнце в спальне» — Восток, «Солнце в гостиной» — Запад. Экземпляры не мешают друг другу: состояние и таймер каждого привязаны к своему сервису.

## 🔎 Как это работает

1. Сценарий срабатывает при запуске хаба, при каждом сохранении сценария и при внешнем изменении привязанной характеристики. Первый расчёт выполняется сразу, а не откладывается до таймера.
2. По текущим дате и времени считается положение Солнца: высота над горизонтом и азимут (направление на Солнце, 0° — Север, отсчёт по часовой стрелке).
3. Солнце считается «в окне», если его высота не ниже порога **и** круговая разность между азимутом Солнца и азимутом окна не больше порога отклонения.
4. Результат записывается в характеристику, если он отличается от текущего значения. Одинаковое значение повторно не пишется — иначе хаб получал бы событие изменения каждую минуту.
5. Ставится одиночный таймер на «интервал пересчёта» минут, который при срабатывании пересчитывает состояние и ставит себя заново.

**Часовой пояс ни на что не влияет.** Расчёт ведётся в абсолютном времени (UTC), поэтому настройка часового пояса хаба не может испортить результат: долгота участвует в расчёте сама. Уравнение времени учтено — именно поэтому положение Солнца в «15:00» отличается изо дня в день.

### Журнал

Все сообщения сценария идут с префиксом **«☀️ Солнце в окне. »**. Каждый пересчёт, изменивший состояние, пишет одну строку с высотой Солнца, его азимутом и отклонением от направления окна. Пересчёт, не изменивший состояние, в журнал не пишет — иначе минутный таймер залил бы его целиком.

### Что происходит при неверных настройках

Если широта, долгота, направление окна, точный азимут или любой из порогов не проходят проверку, сценарий:

1. пишет в журнал **одну строку** с именем параметра, его значением и допустимым диапазоном;
2. **не трогает характеристику вообще** — ни в какое значение, включая первый расчёт при запуске хаба; значение остаётся ровно тем, каким было;
3. **не ставит таймер пересчёта** и гасит уже стоявший.

Сценарий замолкает целиком до следующего сохранения или перезапуска хаба — то есть ровно до того момента, когда вы поправите настройку.

Почему не «выключить флаг»: снятый флаг означает «солнца в окне нет», и ваша автоматизация на него среагирует, — а правда в том, что сценарий не знает ответа. Флаг не должен врать.

| Параметр | Что считается неверным |
|---|---|
| Широта | вне −90…90; пусто или не число |
| Долгота | вне −180…180; пусто или не число |
| Направление окна | значение, которого нет в списке восьми румбов (37, «юг», пусто) |
| Точный азимут окна | непустое значение, не разбираемое в число («юг»); число вне 0…360 (400, −5). **Пустое поле и −1 — не ошибка**, берётся румб |
| Минимальная высота солнца | вне 0…90; пусто или не число |
| Максимальное отклонение от направления окна | вне 1…90 (в том числе 0); пусто или не число |

Крайние значения диапазонов допустимы: широта ±90, долгота ±180, азимут 0 и 360, высота 0 и 90, отклонение 1 и 90. Все восемь румбов из списка, разумеется, тоже.

## ⚠️ Известные ограничения

1. **Точность расчёта — не хуже 0.5° по высоте и азимуту в широтах до ±66°.** Используется приближение солнечных координат USNO/NOAA (точность по склонению и прямому восхождению лучше 0.01° на 1950–2050 годы). Азимут вырождается ровно в двух точках — **на полюсе и в зените**: когда Солнце стоит почти над головой (тропики около полудня) или наблюдатель стоит на самом полюсе, говорить, в какое именно окно оно светит, геометрически бессмысленно, и обещание по азимуту там не действует. Высокая широта сама по себе точности не портит: на Шпицбергене (78°) расчёт расходится с независимой проверкой по алгоритму NOAA на 0.004°.

2. **Атмосферная рефракция и высота над уровнем моря не учитываются.** Рефракция приподнимает видимое Солнце тем сильнее, чем оно ниже: около **0.165° на высоте 5°**, около 0.09° на 10° — планку «меньше 0.1°» она переходит примерно **с 9°**. На пороге по умолчанию (5°) это значит, что настоящее Солнце оказывается чуть выше расчётного и показывается из-за горизонта немного раньше. Для подбора порога на глаз этим можно пренебречь, но при пороге ниже 9° стоит помнить о поправке. Отдельной опции «высота над уровнем моря», как в `DayNight`, здесь нет.

3. **Гистерезиса нет, и он не нужен.** Часовой угол Солнца растёт равномерно — 15° в час, то есть 0.25°/мин; это скорость вращения Земли, а не скорость изменения высоты или азимута. Высота за день растёт и падает, а азимут идёт быстрее всего около местного полудня (в Москве в июне примерно 0.43°/мин, ближе к тропикам — заметно быстрее). Но меняются обе величины плавно, без скачков, поэтому дребезга у порога не возникает.

4. **Точность срабатывания равна интервалу пересчёта.** При интервале 60 минут момент включения определится с точностью до часа, при 1 минуте — до минуты.

5. **В высоких широтах отдельной ветки для полярного дня и ночи нет** — всё решает порог высоты. Полярной ночью флаг снят всегда; полярным днём он поднимается тогда и только тогда, когда Солнце заходит в сектор окна, в том числе ночью.

## 🚫 Чего сценарий не делает

Сознательно, а не «пока не успели». Сценарий считает чистую геометрию — где Солнце и куда смотрит окно:

| Не делает | Почему |
|---|---|
| **Не управляет шторами, подсветкой и кондиционером** | сценарий даёт только флаг; чем именно управлять — решает ваша автоматизация поверх выключателя |
| **Не учитывает облачность** | ни датчик освещённости, ни погодный сервис не опрашиваются: при сплошных облаках флаг всё равно поднят |
| **Не измеряет жару и блики, не учитывает температуру** | это следствия, а не геометрия; будь температура зашита внутрь, тот же флаг перестал бы годиться для «бликов на экране». Датчик спрашивает ваша автоматизация |
| **Не считает атмосферную рефракцию** | вклад мал и предсказуем — цифры в [«Известных ограничениях»](#-известные-ограничения), п. 2 |
| **Не считает затенение соседними домами** | профиль горизонта по азимутам — отдельная задача; типовой случай закрывает нижний порог высоты |
| **Не имеет верхнего порога высоты Солнца** (балкон, козырёк) | по решению пользователя: хватает нижнего |
| **Не имеет смещений «упреждение / задержка, мин»** | по решению пользователя: без смещений |
| **Не имеет комбинированного «угла к стеклу» одним числом** | два отдельных порога — высота и отклонение — понятнее и настраиваются независимо |
| **Не имеет 16 румбов** | восьми румбов плюс точный азимут достаточно для любого окна |
| **Не выдаёт числовую «интенсивность засветки, %»** | флага достаточно под оба названных повода, а у выключателя такой характеристики и нет |

## 📜 История изменений

### 1.0

Первая версия сценария. Состав:

- расчёт положения Солнца на текущие дату и время по приближению USNO/NOAA, в абсолютном времени;
- направление окна румбом или точным азимутом, два независимых порога, пересчёт по таймеру 1…60 минут с гашением старого таймера через поколения;
- опции «Возможность ручного управления», «Менять имя сервиса» и «Инвертировать» — по образцу сценария `DayNight`;
- остановка сценария целиком при неверных координатах, направлении окна или порогах.
