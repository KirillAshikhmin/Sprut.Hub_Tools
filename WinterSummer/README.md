# Сценарий "❄️☀️ Зима/Лето"

Автоматический логический сценарий для Sprut.Hub, который управляет выключателем в зависимости от сезона года.

## Описание

Сценарий автоматически включает и выключает выключатель в зависимости от текущей даты. Позволяет настроить периоды "зима" и "лето" с автоматическим переключением между ними.

## Возможности

- ✅ Автоматическое включение/выключение выключателя по датам
- ✅ Поддержка различных форматов дат:
  - Цифровой формат: `1.12`, `01.03`, `15.6`
  - Текстовый формат: `1 декабря`, `15 марта`, `10 сентября`
- ✅ Корректная обработка перехода между годами
- ✅ Ежесуточная проверка даты в полночь — переключение происходит в сам день границы
- ✅ Гибкая настройка дат начала и окончания сезонов
- ✅ Инверсия: выключатель может работать «наоборот» — выключаться внутри периода
- ✅ Смена имени сервиса на «Зима» / «Лето» по текущему периоду
- ✅ Подробное логирование работы сценария

## Установка

1. Скопируйте содержимое файла `source/WinterSummer.js` в новый логический сценарий в интерфейсе Sprut.Hub
2. Настройте параметры сценария в соответствии с вашими потребностями
3. Активируйте сценарий

## Настройка

### Параметры сценария

| Параметр | Ключ | Тип | По умолчанию | Описание |
|----------|------|-----|--------------|----------|
| **Дата включения** | `startDate` | String | `1.12` | Дата начала периода: `1.12` или `1 декабря` |
| **Дата выключения** | `endDate` | String | `1.03` | Дата окончания периода (включительно): `1.03` или `1 марта` |
| **Менять имя сервиса** | `changeServiceName` | Boolean | `false` | Имя сервиса меняется на «Зима» или «Лето» по текущему периоду |
| **Инвертировать** | `invert` | Boolean | `false` | Внутри периода выключатель выключается, вне периода — включается |

Первым полем в настройках идёт блок **ОПИСАНИЕ** (`desc`, `formType: "status"`) — краткая справка по сценарию прямо в UI, значения не имеет.

### Менять имя сервиса

Имя определяется не состоянием выключателя, а типом периода — так оно остаётся верным и при инверсии, и для летних сценариев:

| Настройка дат | Внутри периода | Вне периода |
|---------------|----------------|-------------|
| Период пересекает конец года (`1.12` – `1.03`) | `Зима` | `Лето` |
| Период внутри одного года (`1.06` – `1.09`) | `Лето` | `Зима` |

Исходное имя сервиса при включении опции теряется — сценарий перезаписывает его при каждом срабатывании.

### Инвертировать

Опция меняет только записываемое в выключатель значение: внутри периода записывается «выключено», вне периода — «включено». Нужна для нормально-замкнутых реле и обратных сценариев (например, «выключить увлажнитель на зиму»). На имя сервиса и на определение периода не влияет.

### Поддерживаемые форматы дат

#### Цифровой формат
- `1.12` - 1 декабря
- `01.03` - 1 марта (с ведущим нулем)
- `15.6` - 15 июня

#### Текстовый формат
- `1 декабря` - 1 декабря
- `15 марта` - 15 марта
- `10 сентября` - 10 сентября

**Примечание:** В текстовом формате названия месяцев должны быть в родительном падеже на русском языке.

### Переменные (`variables`)

Служебное состояние сценария, заполняется автоматически — настраивать вручную не нужно.

| Переменная | Описание |
|------------|----------|
| `midnightTask` | Cron-задача ежесуточной проверки даты (расписание `0 0 0 * * *` — каждую полночь). Создаётся при первом срабатывании сценария |
| `midnightOptionsKey` | Опции, с которыми создана задача (`startDate`, `endDate`, `invert`, `changeServiceName`). Если после правки они изменились, задача пересоздаётся с актуальными значениями |

Переменные сбрасываются при перезагрузке хаба — задача создаётся заново при старте (`onStart: true`).

## Примеры использования

### Пример 1: Отопление зимой
```
Дата включения: 1.12
Дата выключения: 1.03
```
Выключатель будет включен с 1 декабря по 1 марта (включительно).

### Пример 2: Кондиционирование летом
```
Дата включения: 1.06
Дата выключения: 1.09
```
Выключатель будет включен с 1 июня по 1 сентября.

### Пример 3: Сезонное освещение
```
Дата включения: 1 ноября
Дата выключения: 28 февраля
```
Выключатель будет включен с 1 ноября по 28 февраля.

### Пример 4: Отключение увлажнителя на лето (инверсия)
```
Дата включения: 1.06
Дата выключения: 1.09
Инвертировать: включено
Менять имя сервиса: включено
```
С 1 июня по 1 сентября выключатель выключен, в остальное время включен. Имя сервиса — «Лето» внутри периода и «Зима» вне его.

## Когда сценарий срабатывает

1. **Изменилась характеристика `On`** привязанного выключателя (вручную из приложения, физической кнопкой, другой автоматизацией).
2. **Стартовал хаб** и **при каждом сохранении сценария** — из-за `onStart: true`.
3. **Каждую полночь** — по Cron-задаче, которую сценарий регистрирует при первом срабатывании.

Пункт 3 обязателен: наступление даты границы диапазона само по себе никакого события в хабе не порождает и `trigger` не вызывает. Без полуночной задачи выключатель дождался бы правильного состояния только при следующем ручном переключении или перезапуске хаба.

Полуночная задача считает состояние по тем же правилам, что и обычное срабатывание, и той же парой дат — при правке `startDate`/`endDate` и сохранении сценария она пересоздаётся с новыми значениями.

## Логика работы

1. Сценарий проверяет текущую дату (без учета года)
2. Сравнивает текущую дату с настроенными датами включения и выключения
3. Если даты не пересекают год (например, 1.06 - 1.09):
   - Выключатель включен, если текущая дата находится в диапазоне
4. Если даты пересекают год (например, 1.12 - 1.03):
   - Выключатель включен, если текущая дата >= даты включения ИЛИ <= даты выключения

### Пример с переходом через год

При настройке:
- Дата включения: `1.12` (1 декабря)
- Дата выключения: `1.03` (1 марта)

Выключатель будет включен:
- С 1 декабря по 31 декабря
- С 1 января по 1 марта

## Логирование

Сценарий ведет подробные логи:
- Текущая дата
- Настроенные даты включения и выключения
- Текущий период («Зима» / «Лето») и принимаемое решение (включить/выключить)
- Изменения состояния выключателя

Логи можно просмотреть в интерфейсе Sprut.Hub в разделе "Логи".

## Ограничения

- Сценарий работает только с выключателями (HS.Switch)
- Поддерживает только характеристику включения/выключения (HC.On)
- Даты указываются без учета года
- Максимальный день в месяце: 31 (корректность не проверяется для конкретных месяцев)
- Полуночная задача живёт до перезагрузки хаба: после рестарта она создаётся заново первым срабатыванием (`onStart: true`), но если хаб был выключен в момент наступления границы диапазона, состояние выставится не в полночь, а при старте
- Момент полуночи берётся по системным часам хаба (его часовому поясу)

## Устранение неполадок

### Сценарий не работает
1. Проверьте, что сценарий активирован
2. Убедитесь, что выключатель имеет сервис Switch с характеристикой On
3. Проверьте логи на наличие ошибок

### Неправильная дата
1. Убедитесь, что формат даты соответствует поддерживаемым
2. Для текстового формата используйте названия месяцев в родительном падеже
3. Проверьте, что день находится в диапазоне 1-31, месяц 1-12

### Неожиданное поведение
1. Проверьте логи сценария
2. Убедитесь в правильности настройки дат
3. Проверьте текущую дату системы
