# Кодовый замок (`CodeLock`)

**Дата:** 2026-08-17
**Статус:** реализовано в версии 1.1; спека отражает состояние после многоагентного ревью

## 1. Цель и контекст

Сценарий позволяет **разблокировать целевое устройство вводом кода на физических кнопках**: открыть замок, снять сигнализацию с охраны, включить выключатель, открыть ворота. Код — это последовательность нажатий на выбранных кнопках, где каждый шаг задан парой «кнопка + тип нажатия» (одиночное / двойное / долгое).

Типы нажатий сценарий **не измеряет сам** — он получает готовые события `ProgrammableSwitchEvent` от кнопок хаба (`0` = одиночное, `1` = двойное, `2` = долгое). Разделение single/double/long выполняет сам хаб (у встроенной логики «Виртуальная кнопка» — `DoubleClickTime` 350 мс, `LongClickTime` 1000 мс).

Ключевое свойство `ProgrammableSwitchEvent`: это **событийная** характеристика, два одиночных нажатия подряд приходят как два независимых события, а не как «то же самое значение, которое незачем применять». Без этого коды вида `SS` были бы невозможны.

### 1.1. Целевые типы (подтверждено по `sh_types.json`)

| Сервис | Характеристика-якорь | Значение «разблокировать» |
|---|---|---|
| `LockMechanism` | `LockTargetState` | `0` (Открыто) |
| `SecuritySystem` | `SecuritySystemTargetState` | `3` (Выкл.) |
| `Switch` / `Lightbulb` / `Outlet` | `On` | `true` |
| `GarageDoorOpener` | `TargetDoorState` | `0` (Открыто) |

Кнопки-источники — сервисы `StatelessProgrammableSwitch` и `Doorbell`, у обоих required-характеристика `ProgrammableSwitchEvent` (`Integer`, `validValues` 0/1/2).

## 2. Архитектура: якорь + подписка

Канонический паттерн репозитория (образцы — `ExternalTempSensor`, `PulseCounterButton`): сценарий **привязывается к целевому устройству**, а на источники событий подписывается программно.

- **Якорь.** `sourceServices: [HS.LockMechanism, HS.SecuritySystem, HS.Switch, HS.Lightbulb, HS.Outlet, HS.GarageDoorOpener]`, `sourceCharacteristics: [HC.LockTargetState, HC.SecuritySystemTargetState, HC.On, HC.TargetDoorState]`. При `onStart: true` `trigger` вызывается на старте хаба и при каждом сохранении сценария — это точка инициализации.
- **Характеристика для записи выбирается по типу сервиса**, а не по тому, с какой характеристики пришёл `trigger`. У `GarageDoorOpener` `LockTargetState` — допустимая необязательная характеристика, и хаб вызывает `trigger` отдельно для каждой подходящей: `LockMechanism → LockTargetState`, `SecuritySystem → SecuritySystemTargetState`, `GarageDoorOpener → TargetDoorState`, `Switch`/`Lightbulb`/`Outlet` → `On`. Если тип сервиса неизвестен, якорем остаётся сам `source`.
- **Подписка.** `Hub.subscribeWithCondition("", "", [HS.StatelessProgrammableSwitch, HS.Doorbell], [HC.ProgrammableSwitchEvent], handler)` оформляется **один раз**, под флагом `variables.subscribed`. Фильтрация «наших» кнопок — по UUID сервиса внутри обработчика.
- **Актуальность опций.** Обработчик замкнут на объект `variables`, а не на `options`. На каждом не-self вызове `trigger` записывает `variables.opts = options` и `variables.code = parseCode(options.code)`. Поскольку при `onStart: true` сохранение сценария вызывает `trigger`, **смена кода или состава кнопок в UI подхватывается сохранением, без перезагрузки хаба**.
- **Подписка оформляется безусловно**, даже при невалидной конфигурации. Обработчик сам выходит, пока `variables.code === null`. Иначе после исправления настроек пришлось бы перезагружать хаб.
- **Self-echo.** Сценарий пишет в ту же характеристику, на которой висит, — собственная запись вызывает `trigger` повторно. Первой строкой `trigger` стоит `if (isSelfChanged(context)) return;` (эталон `PassthroughSwitch` / `PulseCounterButton`).

Чистый **логический** сценарий, без глобальной части.

```

  README.md
  source/CodeLock.js          # логический сценарий (единственный файл кода)
  .tests/config.json          # logic-only
  .tests/SPEC.md              # поведенческая спецификация для black-box тестов
  .tests/code-lock.test.js    # тесты от спецификации
  .tests/preset.json          # фикстура для ручной проверки в веб-UI
  publish.json                # создаётся `./publish CodeLock --init`
  Кодовый замок.json          # экспорт, генерируется `./publish` — вручную не трогаем
```

## 3. Блок `info`

Название: `🔐 Кодовый замок` / `🔐 Code lock`. Версия `1.1`, автор `@BOOMikru`, `onStart: true`.

### 3.1. Опции (порядок в UI)

| Ключ | Тип | Дефолт | Название |
|---|---|---|---|
| `desc` | `String`, `formType: "status"` | `""` | `  ОПИСАНИЕ` |
| `code` | `String`, `maxLength: 128` | `""` | Код |
| `allowExtraPresses` | `Boolean` | `false` | Разрешить произвольные нажатия до и после кода |
| `button1` … `button9`, `button0` | `String`, `formType: "list"` | `""` | Кнопка 1 … Кнопка 9, Кнопка 0 |
| `enterButton` | `String`, `formType: "list"` | `""` | Кнопка ввода |
| `pressTimeout` | `Integer`, 0–300, шаг 1 | `10` | Задержка на ввод, с |
| `restoreDelay` | `Integer`, 0–3600, шаг 1 | `0` | Вернуть прежнее состояние через, с |
| `debug` | `Boolean` | `false` | Отладочный лог |

Поля кнопок идут в порядке **1, 2, …, 9, 0** — как на телефонной клавиатуре. Списки значений собираются функцией уровня модуля (над блоком `info`) из всех сервисов `StatelessProgrammableSwitch` / `Doorbell`, имеющих `ProgrammableSwitchEvent`; первый элемент — «Не выбрано» со значением `""`. Значение опции — UUID сервиса в формате `"<aid>.<sid>"`. Список обновляется на старте хаба и при сохранении сценария.

`pressTimeout = 0` — таймаут выключен. `restoreDelay = 0` — автовозврат выключен.

### 3.2. Переменные

```js
variables: {
  subscribed: false,     // подписка оформлена
  opts: null,            // снимок options последнего не-self trigger
  code: null,            // разобранный код: массив шагов или null при ошибке конфигурации
  buffer: [],            // накопленные нажатия
  lastPressAt: 0,        // время последнего учтённого нажатия, мс
  blocked: false,        // строгий режим: ввод заблокирован до паузы
  restoreTask: undefined,// задача автовозврата
  restoreValue: undefined// значение якоря до срабатывания
}
```

Все переменные сбрасываются при перезагрузке хаба: буфер пуст, подписка оформляется заново.

## 4. Парсер кода

Вход — строка опции `code`. Выход — массив шагов `[{btn, type}]`, где `btn` — символ `'0'`–`'9'`, `type` — `0` (single) / `1` (double) / `2` (long); либо `null`, если строка невалидна.

Разбор посимвольный, регистр не важен. Разделители не нужны для однозначности (номер кнопки всегда одна цифра), но допускаются и просто пропускаются: пробел, табуляция, `,` `.` `-` `+` `_`. Кириллические `С`, `Д`, `Л` — синонимы `S`, `D`, `L`: код часто набирают, не переключая раскладку.

```
parseCode(raw):
  если raw не строка или пустая после trim → null
  для каждого символа c из raw.toUpperCase():
    c — разделитель            → пропустить
    c — цифра '0'..'9'         → добавить шаг {btn: c, type: 0, typed: false}
    c — 'S' | 'D' | 'L'        → t = 0 | 1 | 2
        нет шагов              → добавить шаг {btn: '1', type: t, typed: true}
        последний шаг typed    → добавить шаг {btn: <btn последнего>, type: t, typed: true}
        иначе                  → последнему шагу type = t, typed = true
    любой другой символ        → null (ошибка разбора)
  шагов 0 → null
  вернуть шаги (флаг typed отбрасывается)
```

Правила, которые из этого следуют: **цифра без буквы — одиночное нажатие**; **буква без цифры — кнопка 1**; повторная буква подряд открывает новый шаг на той же кнопке.

| Ввод | Результат |
|---|---|
| `SSDL` | `1S 1S 1D 1L` |
| `1S 2S 1D 2S` | `1S 2S 1D 2S` |
| `12357` | `1S 2S 3S 5S 7S` |
| `0D9L` | `0D 9L` |
| `1SS` | `1S 1S` |
| `SS1` | `1S 1S 1S` |
| `` (пусто) | ошибка конфигурации |
| `1X` | ошибка конфигурации |

Шаг сравнивается как строковый ключ `btn + ":" + type` (например `"1:0"`), последовательность — как `join("|")`. Этого достаточно и для равенства, и для поиска подпоследовательности.

Ограничение: **не более 32 шагов** (`MAX_CODE_STEPS`).

## 5. Режимы матчинга

Комбинация двух настроек — выбрана ли «Кнопка ввода» и включена ли галка «Разрешить произвольные нажатия до и после кода»:

| Кнопка ввода | Галка | Поведение |
|---|---|---|
| нет | **вкл** | скользящее окно: буфер хранит последние N нажатий (N = длина кода), после каждого нажатия сравнивается с кодом целиком |
| нет | **выкл** | строгий режим: нажатия сверяются по позиции с начала кода; первое несовпадение блокирует ввод до паузы строго больше `pressTimeout` |
| есть | **вкл** | по «Ввод» код ищется как **непрерывная подпоследовательность** буфера |
| есть | **выкл** | по «Ввод» буфер должен быть **точно равен** коду |

Наивный «рестарт с текущего нажатия» вместо скользящего окна не эквивалентен ему и был отвергнут: для кода `1S 1S 2S` и ввода `1S 1S 1S 2S` окно даёт совпадение, а рестарт теряет уже набранный префикс и не срабатывает.

Строгий режим — единственный в v1.0 тормоз против перебора: со скользящим окном непрерывное долбление кнопками рано или поздно накроет любой код (последовательность де Брёйна), а строгий режим требует выждать паузу после каждой ошибки.

## 6. Обработка события кнопки

```
handler(charSource, value):
  uuid = charSource.getService().getUUID()
  opts = variables.opts;  code = variables.code
  если code === null → выход (конфигурация невалидна)

  isEnter = opts.enterButton && uuid === opts.enterButton
  если isEnter и value !== 0 → выход              // двойное/долгое на кнопке ввода игнорируются полностью
  если не isEnter:
      btn = поиск uuid среди opts.button1..button9, button0
      если не найдено → выход                     // чужая кнопка: буфер, паузы и блокировка не трогаются

  now = Date.now()
  gap = variables.lastPressAt ? now - variables.lastPressAt : Infinity
  variables.lastPressAt = now                     // обновляется и на заблокированных нажатиях
  если opts.pressTimeout > 0 и gap > pressTimeout * 1000:
      buffer = [];  blocked = false                // истечение паузы сбрасывает ввод и снимает блокировку

  далее выполняется РОВНО ОДНА из трёх веток ниже — по §5

  --- режим без кнопки ввода, галка ВКЛ (скользящее окно) ---
  buffer.push(шаг);  пока buffer.length > N: buffer.shift()
  если buffer.length === N и buffer совпал с code → УСПЕХ, buffer = []

  --- режим без кнопки ввода, галка ВЫКЛ (строгий) ---
  если blocked → выход
  если шаг === code[buffer.length]:
      buffer.push(шаг)
      если buffer.length === N → УСПЕХ, buffer = []
  иначе:
      blocked = true;  buffer = []

  --- режим с кнопкой ввода ---
  если не isEnter:
      buffer.push(шаг);  пока buffer.length > 64: buffer.shift()
  иначе:
      ok = галка ВКЛ ? (code — подпоследовательность buffer) : (buffer точно равен code)
      если ok → УСПЕХ
      buffer = []                                  // буфер очищается и при успехе, и при провале
```

Блокировка в строгом режиме снимается **только** паузой строго больше `pressTimeout` между нажатиями (пауза ровно в `pressTimeout` ещё допустима — сброс идёт по `gap > pressTimeout * 1000`). Поскольку `lastPressAt` обновляется даже на игнорируемых из-за блокировки нажатиях, непрерывное долбление кнопками никогда не разблокирует ввод — это и есть цель режима.

## 7. Успех и автовозврат

```
УСПЕХ:
  target = значение «разблокировать» по типу характеристики-якоря (§1.1)
  если нет активного restoreTask:
      variables.restoreValue = anchor.getValue()   // запоминаем состояние ДО срабатывания
  anchor.setValue(target)
  console.info(...)
  если opts.restoreDelay > 0:
      clearTimeout(variables.restoreTask)
      variables.restoreTask = setTimeout(→ anchor.setValue(variables.restoreValue)
                                           variables.restoreTask = undefined, restoreDelay * 1000)
```

Задача автовозврата обнуляет `variables.restoreTask` при срабатывании — иначе следующий успешный ввод счёл бы автовозврат всё ещё запланированным и не перечитал бы `restoreValue`.

- `restoreValue` перечитывается только когда автовозврат **не** запланирован. Иначе повторный успешный ввод во время ожидания сохранил бы уже разблокированное состояние и автовозврат стал бы бессмысленным; вместо этого таймер просто перезапускается с прежним `restoreValue`.
- Если устройство уже было разблокировано на момент ввода, автовозврат вернёт «разблокировано» и фактически ничего не изменит — прямое следствие семантики «вернуть как было».
- Любой **не-self** вызов `trigger` (ручное управление устройством, старт хаба, сохранение сценария) отменяет отложенный автовозврат: `clearTimeout(restoreTask)`, `restoreTask = undefined`. Ручное вмешательство пользователя имеет приоритет над таймером сценария.
- Если тип характеристики-якоря не из таблицы §1.1 — `console.error` и никаких записей.

## 8. Ошибки конфигурации

Проверяются в `trigger` на каждом не-self вызове. При любой ошибке: `console.error` с текстом проблемы, `variables.code = null` — сценарий не реагирует на нажатия до исправления настроек и сохранения сценария.

1. Код пустой или не разбирается (§4).
2. Код длиннее 32 шагов.
3. Код ссылается на кнопку, поле которой не заполнено (например `3S` при пустой «Кнопка 3»).
4. Одна и та же кнопка выбрана более чем в одном поле — включая поле «Кнопка ввода».
5. Галка **выкл** + кнопка ввода **не выбрана** + `pressTimeout = 0`: блокировку после ошибки нечем снять, ввод залипнет навсегда.

## 9. Логирование

| Событие | Уровень |
|---|---|
| Верный код, устройство разблокировано | `console.info` |
| Неверный код по нажатию «Ввод» (на непустом наборе) | `console.info` |
| Нажатие «Ввод» на пустом наборе | только при `debug: true` |
| Ошибка конфигурации | `console.error` |
| Каждое учтённое нажатие, содержимое буфера, сброс по таймауту, блокировка/разблокировка строгого режима, планирование и срабатывание автовозврата | только при `debug: true` |

Блокировка строгого режима намеренно не пишется в `info`: иначе каждое случайное нажатие мимо кода засоряло бы журнал.

## 10. Известные ограничения

- Разделение single/double/long выполняет хаб, а не сценарий. Если кнопка не отдаёт двойные/долгие события, коды с `D`/`L` работать не будут.
- В v1.0 нет счётчика неудачных попыток и временной блокировки после серии ошибок (отложено осознанно, см. §11).
- В режиме скользящего окна перебор нажатий теоретически вскрывает код без единой паузы.
- Смена опций подхватывается сохранением сценария; правка кода «на живую» без сохранения не применяется.
- Все накопленные нажатия теряются при перезагрузке хаба.
- **Запланированный автовозврат не переживает перезагрузку хаба и сохранение сценария**: движок останавливает задачи логики и пересоздаёт `variables` (`TR_LogicRuntime`), поэтому открытый кодом замок останется открытым. Восстановить состояние на `onStart` нечем — `restoreValue` живёт только в `variables`. Ограничение документировано в README; для замков рекомендуется штатное автозапирание устройства.
- Кнопка ввода реагирует только на одиночное нажатие; двойное и долгое на ней игнорируются полностью.

## 11. Отложено (не входит в v1.0)

- Счётчик неудачных попыток с блокировкой ввода на N минут и уведомлением.
- Второй код для обратного действия (запереть / поставить на охрану).
- Выбор действия при верном коде (сейчас всегда «разблокировать / включить / открыть»).
